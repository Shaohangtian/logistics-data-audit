# 智能物流数据集 数据质量审计报告

审计对象：`data/raw/smart_logistics_dataset.csv`（1000 行 × 16 列）
工具：本仓库 `src/audit.py`（五项检测，见 `tests/test_audit.py`，30 个测试通过）

**一句话结论**：这份数据集存在严重目标泄漏、且大量字段是随机生成的，
**不能用于建模，也不支持产出业务建议**。以下是完整证据链。

## 一、核心发现

1. **目标变量可由两个字段完全复现，命中率 1000/1000**

   ```python
   Logistics_Delay = (Shipment_Status == 'Delayed') OR (Traffic_Status == 'Heavy')
   ```

   9 个 (路况, 运输状态) 组合中，**没有任何一格同时出现 0 和 1**。
   → 这是典型**目标泄漏**：答案本来就写在特征里，任何模型都会得到虚高的准确率。

2. **10 个数值字段中有 9 个是均匀随机数**

   实际标准差与均匀分布理论值 `(上限 − 下限) / √12` 的比值，
   在这 9 个字段上全部落在 **[0.959, 1.038]**，几乎精确等于 1。
   真实观测数据几乎不会如此"标准"。

   > 未纳入的 1 个是 `User_Purchase_Frequency`（取值 1–10 的离散列），
   > 其比值为 1.1298 —— 小区间上的离散均匀分布不满足连续均匀的标准差公式，
   > 属于方法适用范围问题，不代表它是真实观测值。

3. **`Logistics_Delay_Reason` 是随机贴的标签**

   与"是否延迟"独立（卡方检验 **p = 0.9925**），四个取值分布近乎均匀：

   | 取值 | 占比 |
   |---|---|
   | Weather | 26.7% |
   | None | 26.3% |
   | Traffic | 23.6% |
   | Mechanical Failure | 23.4% |

4. **时间维度不存在可利用的规律**

   月度 p = 0.5869、小时 p = 0.6735、星期 p = 0.3535，三者均不显著。
   （源项目完全未涉及此维度，本报告补齐。）

5. **移除泄漏字段后模型跌回基线**（5 折分层交叉验证）

   | 实验 | 特征数 | 准确率 |
   |---|---|---|
   | A 用泄漏字段 | 2 | **1.0000** |
   | B 删掉泄漏字段 | 7 | **0.5290** |
   | C 多数类基线 | 7 | **0.5660** |

   删掉泄漏字段后不仅没有超过基线，反而**低于基线 3.7 个百分点** ——
   这是随机噪声的典型表现：模型只能在噪声上过拟合，还不如不学。
   实验代码见 `notebooks/03_synthetic_check.ipynb` 末尾。

## 二、数据质量说明

| 问题 | 规模 |
|---|---|
| 逻辑矛盾记录（有原因未延迟 / 延迟但原因为 `None`） | **465 行，占 46.5%** |
| 原因字段为字符串 `None`（**有效取值，非缺失值**） | 263 行 |
| `Traffic_Status == 'Heavy'` 组的延迟率 | **327/327 = 100.00%**（无一反例） |
| 数值字段取值区间宽度为 10 的整数倍 | 8/9（例外：Temperature 区间 18–30，宽度 12） |
| 真正的缺失值（NaN） | **0 个** |

**读数据时必须注意**：原因字段里的 `None` 是有效取值。
`pandas.read_csv` 默认会把字符串 `None` 转成 `NaN`，从而抹掉这个取值，
并让后续 `dropna()` 误删有效数据。正确读法：

```python
df = pd.read_csv(path, keep_default_na=False, na_values=[''])
```

## 三、业务建议

**本数据集为合成数据。**

其正确用途是作为分析方法的练习材料，以及数据陷阱（目标泄漏、
合成数据识别）的教学案例。

若需产出业务结论，必须改用真实采集的物流运营数据。
